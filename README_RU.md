# Исправленная версия gardening-termin

## Что исправлено

Проект теперь использует **один Flask backend**: `app.py + models.py + admin.py`. Файл `vercel_app.py` является только точкой входа Vercel и больше не содержит дублирующиеся модели/роуты. Это устраняет конфликт между production-версией и локальной версией проекта.

При запуске создаются отсутствующие таблицы/колонки, а `yangi.json` синхронизируется с БД по версии `DATASET_VERSION`. Импортируются все доступные поля: узбекское и английское определения, примеры, произношение, этимология, части речи, области применения и семантические связи. URL изображений автоматически связываются с терминами из `blob_urls_correct.txt`, включая безопасное сопоставление вариантов с научными названиями в скобках и небольшими опечатками.

На главной странице больше нет искусственного ограничения 50 слов на букву. Основной поиск из `app.py` также не ограничен 20 результатами. Страницы областей используют полную выборку.

Админ-панель снова работает через Blueprint `admin`. Доступны оба URL: `/admin/` и `/admin/dashboard`. Dashboard получает правильные переменные, функцию `now()` и все endpoints (`admin.words`, `admin.categories`, `admin.import_export` и др.). Дата последнего добавления безопасно отображается даже у старых записей без `created_at`.

## Обязательные Environment Variables в Vercel

Создайте в **Project → Settings → Environment Variables**:

- `SECRET_KEY` — длинная случайная строка.
- `ADMIN_USERNAME` — например `admin`.
- `ADMIN_PASSWORD` — новый сложный пароль. Не оставляйте `admin123`.
- `DATABASE_URL` — URL постоянной PostgreSQL БД (рекомендуется Neon/Postgres). Это **обязательно для постоянного сохранения изменений из админ-панели**.
- `BLOB_READ_WRITE_TOKEN` — новый токен Vercel Blob, если хотите загружать новые изображения из админ-панели.
- `AUTO_SYNC_DATA=1` — оставить включённым.
- `DATASET_VERSION=2026-08-23-v3` — при следующем изменении `yangi.json` увеличьте версию, например `v4`.

Если `DATABASE_URL` не задан, сайт на Vercel всё равно запустится с SQLite в `/tmp` и автоматически загрузит 1100 терминов, но изменения из админ-панели могут исчезнуть после перезапуска serverless-инстанса.

## Важно: токен Blob

Старый write-token был записан в исходных upload-скриптах предыдущей версии. Его необходимо **отозвать/перегенерировать** в Vercel. В исправленной папке токен в коде не хранится.

## Развёртывание

1. Замените старые production-файлы содержимым этой папки.
2. Убедитесь, что структура `templates/` и `templates/admin/` сохранена.
3. Добавьте Environment Variables выше.
4. Выполните новый Deploy в Vercel.
5. Откройте `/word/Agrokimyo`. Должны отображаться `Agrochemistry`, `noun`, pronunciation, English definition, etymology, example и изображение (если URL сопоставлен).
6. Откройте `/admin/dashboard` и войдите новым `ADMIN_USERNAME`/`ADMIN_PASSWORD`.
7. Для ручной повторной синхронизации локально/на сервере используйте `python sync_data.py`.

## Изображения

`image_mapping_report.csv` показывает результат сопоставления 1100 терминов с `blob_urls_correct.txt`. В текущем наборе удалось безопасно сопоставить около 1040 терминов. Строки со статусом `missing` означают, что в переданном файле URL нет достаточно надёжного совпадения. Если соответствующее изображение действительно есть в Vercel Blob, добавьте строку вида:

`Название термина = https://...blob.vercel-storage.com/file.jpg`

в `blob_urls_correct.txt`, увеличьте `DATASET_VERSION` и сделайте redeploy.

## Исправление изображений Vercel Blob (v4)

Эта сборка больше не строит URL изображения из BLOB_STORE_ID. При запуске приложение использует `BLOB_READ_WRITE_TOKEN`, получает реальный список объектов через `vercel_blob.list(...)`, берет фактические поля `pathname` и `url`, сопоставляет их с терминами и обновляет `Word.image_url` в PostgreSQL.

Важно: синхронизация Blob выполняется даже если `DATASET_VERSION` уже совпадает с версией в БД, поэтому старые ошибочные URL автоматически заменяются на реальные после нового deployment.

Для локального PyCharm изображения из Vercel Blob будут автоматически синхронизироваться только если в локальном окружении задан `BLOB_READ_WRITE_TOKEN`. На Vercel он уже добавлен как Environment Variable, поэтому production deployment синхронизирует изображения автоматически.

После push в GitHub дождитесь нового deployment и откройте `/word/Agrokimyo`. Если приложение уже было запущено на старом deployment, сделайте Redeploy после push.
